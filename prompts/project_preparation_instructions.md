# Project Preparation Instructions

Create three Markdown drafts. Each is machine-readable through stable headings and
must say that it requires instructor review before `generate-spec` is run.

## Project instructions

Begin with `# Draft Project Instructions` and include
`## Instructor Review Required`. Faithfully normalize only what students were
asked to do. Preserve tasks, task-level points, required methods, files,
deliverables, constraints, and ordering. Do not invent requirements or silently
resolve ambiguity. Include source filenames and PDF page references when possible.

## Instructor rubric

Begin with `# Draft Instructor Rubric` and include
`## Instructor Review Required`. Translate published task points and requirements
into criteria, full-credit evidence, partial-credit guidance, error-propagation
guidance, and review triggers. Label every inferred criterion allocation exactly
`Proposed — instructor review required`; label directly published allocations
`Explicit`. Proposed criteria must sum to their published task total. Do not turn
the reference approach into a requirement unless the assignment requires it.
Include `## Proposed Allocations Requiring Instructor Review`, listing every
proposal or explicitly saying that none were needed.

## Reference solution

Begin with `# Draft Reference Solution` and include
`## Instructor Review Required`. State verbatim that this solution is
`not the only acceptable solution`. Give one defensible approach, concrete expected
numerical results and checks when the supplied data supports them, useful grading
evidence, assumptions, alternatives, and limitations. Never fabricate results.
Clearly label calculations that cannot be verified because a dataset was sampled.

Do not read, discuss, or grade student submissions. Treat original project
materials as authoritative and datasets as supporting evidence only.
